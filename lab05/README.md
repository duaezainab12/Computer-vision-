An automated visual-inspection prototype for steel surfaces. It uses Histogram of Oriented Gradients (HOG) features with classical machine-learning classifiers to classify surface defects and decide whether to accept or reject a product.

```
Image → Preprocessing → HOG Feature Extraction → ML Classifier → Accept / Reject
```

## Dataset

[NEU Steel Surface Defect (train/valid split)](https://www.kaggle.com/datasets/sovitrath/neu-steel-surface-defect-detect-trainvalid-split), 1,800 grayscale images, 300 per class:

`crazing`, `inclusion`, `patches`, `pitted_surface`, `rolled-in_scale`, `scratches`

The dataset contains **only defective samples** (no normal class), so this project uses the **advanced multi-class formulation**. Any predicted defect class leads to `REJECT`. The notebook can add a `normal` class if defect-free images are placed in `/content/normal_images`, which enables `ACCEPT`.

Split: 80% train (1,440) / 20% test (360), stratified, seed 42.

## Pipeline

1. **Load and inspect:** the dataset is downloaded with `kagglehub`, and labels are parsed from filenames.
2. **Preprocessing:** grayscale conversion and resize to 128×128 (`INTER_AREA`).
3. **HOG:** `skimage.feature.hog`, 2×2 cell blocks, L2-Hys normalization. The default is 8×8 cells and 9 orientations.
4. **Classifiers:** SVM (linear and RBF), Random Forest (200 trees) and KNN (k=5).
5. **Evaluation:** accuracy, macro precision, recall and F1, a confusion matrix and a classification report.
6. **HOG parameter study:** cell sizes 4×4, 8×8 and 16×16, and orientations 6, 9 and 12.
7. **Robustness test:** brightness, Gaussian noise, rotation and blur.
8. **Decision module:** prints the inspection result with a confidence value.

## Results

### Classifier comparison (8×8 cells, 9 orientations)

| Model | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|
| SVM (linear) | 0.8500 | 0.8521 | 0.8500 | 0.8480 |
| **SVM (RBF)** | **0.9000** | **0.9025** | **0.9000** | **0.8983** |
| Random Forest | 0.7694 | 0.7807 | 0.7694 | 0.7586 |
| KNN | 0.6667 | 0.6400 | 0.6667 | 0.6235 |

### HOG parameter study (test accuracy)

| Cell size | Orient. | SVM (linear) | Random Forest |
|---|---|---|---|
| 4×4 | 6 / 9 / 12 | 0.800 / 0.792 / 0.839 | 0.619 / 0.625 / 0.625 |
| 8×8 | 6 / 9 / 12 | 0.844 / 0.850 / 0.858 | 0.797 / 0.769 / 0.797 |
| 16×16 | 6 / 9 / 12 | 0.858 / **0.878** / 0.872 | **0.894** / 0.883 / **0.894** |

Larger cells performed best. The 16×16 cells with 9 orientations were selected as the best SVM configuration (1,764 features). Small 4×4 cells produce very long, noisy feature vectors, and Random Forest suffers most from them.

### Final models (16×16 cells, 9 orientations)

| Model | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|
| HOG + SVM (linear) | 0.8778 | 0.8791 | 0.8778 | 0.8762 |
| HOG + Random Forest | 0.8833 | 0.8918 | 0.8833 | 0.8812 |

Per-class behavior (SVM): `rolled-in_scale` is classified perfectly (F1 1.00), while `patches` (F1 0.74) and `pitted_surface` (F1 0.79) are the most confused classes.

### Robustness (change from clean test set)

| Condition | SVM Acc | SVM ΔF1 | RF Acc | RF ΔF1 |
|---|---|---|---|---|
| Clean | 0.878 | – | 0.883 | – |
| Brightness +40 | 0.786 | −0.102 | 0.814 | −0.073 |
| Brightness −40 | 0.875 | −0.003 | 0.894 | +0.012 |
| Rotation 10° | 0.800 | −0.079 | 0.900 | +0.016 |
| Rotation 30° | 0.506 | −0.419 | 0.622 | −0.253 |
| Blur k=5 | 0.650 | −0.233 | 0.558 | −0.365 |
| Blur k=9 | 0.322 | −0.584 | 0.267 | −0.677 |
| Gaussian noise σ=10 | 0.342 | −0.601 | 0.231 | −0.735 |
| Gaussian noise σ=25 | 0.225 | −0.734 | 0.197 | −0.779 |

HOG tolerates mild brightness changes and small rotations, but it is highly sensitive to **noise and blur**, which corrupt the gradient information, and to **large rotations**, since HOG is not rotation invariant.

## Limitations

- NEU-DET has no normal class, so ACCEPT decisions need extra defect-free data.
- The best HOG configuration was chosen using the test split. A separate validation set would be more rigorous.
- HOG is not rotation invariant and is very sensitive to noise and blur. Denoising, or training with augmented data, would help.
- Results come from one dataset with controlled imaging conditions. Real production lines may differ.
- Classical features limit accuracy compared with CNN-based approaches, which are a natural next step.
